# Azerbaijani CV, resume and letter quality — measurements, the change, and what still needs a native reader (9 October 2026)

**Generation is still OFF in production** (`DOCUMENT_GENERATION_ENABLED=false`). Nothing here claims natural Azerbaijani: mechanical checks catch known slips; only a native reader can approve the samples.

## 1. What was measured (real provider, synthetic candidates, real public vacancies)
Candidates: an accountant (moderate evidence), a sales manager (rich: 3 roles, project, volunteering, certificate, story) and a sparse profile (one role, two skills, no motivation), each against one real public vacancy (Böyük mühasib, Baş Satış Meneceri, WMS Operator). CV and letter for each = 6 documents per run. Provider requests this round: 52 (screening 15, model-written arm with gates 18, composed arm 6 + 7 + 6); tokens per composed document 0.5–1.4 k prompt + 0.5–2.4 k completion (the earlier model-written pair cost about 8 k).
| Arm | Result |
|---|---|
| **Other models on the same key (current code, 1 CV + 1 letter each)** | `google/gemma-4-31b-it`: every call timed out (3 × 120 s); `moonshotai/kimi-k3`: HTTP 400 on every request; `z-ai/glm-5.3`: three unusable answers; `mistralai/mistral-large-2-instruct`: rejected at once; `nvidia/nemotron-3-ultra-550b-a55b` was queued but not reached before the run was stopped. Only the current `nvidia/nemotron-3-super-120b-a12b` answers reliably, so **no alternative model is proposed**: none was usable, and none is claimed to be better |
| **Model-written Azerbaijani + language gate, 3 attempts with feedback** | 4 of 6 documents produced, 2 refused after three attempts (no document, refunded). The produced ones were still not acceptable: "murojaat edirem" (for "müraciət edirəm"), "Kolleci'nde", "proyektimiz", a changed meaning ("tapıb düzəldim" for "müəyyən etdi"), a nonsense CV sentence ("Azərbaycan və Rus dillərində səlis biliklə … tamamlayıb"), person and tense mixed. Most of these cannot be detected without a dictionary (none exists offline for Azerbaijani), so a stricter gate would only refuse more |
| **Composed from the candidate's and vacancy's own wording, model gives ids only** | 6 of 6 produced, each with one provider request (one retry after a timeout); every word is the candidate's, the vacancy's or one of the fixed frames below. No unsupported number or term, no Turkish form, no English function word |

## 2. The change
* **CV / resume (Azerbaijani):** the candidate's own bullets, ordered by relevance (the model returns a 0-based order; code validates it; outage → keyword ranking); skills ordered the same way; no generated summary (header and skills section already carry it).
* **Letter (Azerbaijani):** fixed frames + the vacancy's own requirement lines (verbatim, bullets first, no numbers/links/addresses) + the candidate's own evidence (verbatim; a final simple-past verb takes "-m" only where the subject is the candidate: passives and results such as "oldu", "azaldı", "bağlandı" stay as written) + the candidate's own motivation (verbatim). The model only pairs "requirement index ↔ evidence id".
* **Frames (for the native reader to approve or rewrite):**
  1. `{Şirkət} tərəfindən elan olunmuş {Vəzifə} vakansiyasına müraciət edirəm.` (+ the candidate's motivation, if any)
  2. `Elanda «{tələb}» tələbi qeyd olunub. Bu sahədə təcrübəm: {fakt}.`
  3. `Elanda həmçinin «{tələb}» tələbi var. Bu istiqamətdə təcrübəm: {fakt}.`
  4. no match: `Təcrübəmdən nümunələr: {fakt}; {fakt}.`
  5. `Təcrübəmi və motivasiyamı görüşdə ətraflı izah etməyə hazıram.` (salutation and closing are the existing fixed ones)
* **Unchanged:** other languages and short answers to application questions keep the model-written path (now with the language gate: Turkish forms, English function words, present tense in an ended role and a letter that does not name the position or employer are refused and repeated with the offending words, 3 provider calls at most; still rejected → `LANGUAGE_QUALITY` / `NOT_RELEVANT`: the row is FAILED, no document, nothing committed, the reserved unit refunded). Candidate-approved paragraphs, snapshots, idempotency and allowance accounting are untouched. `TAILOR_AZ_FREE_WRITING=true` restores model prose (evaluation only).
* **PDF fixes found by looking at the pages:** more space between experience entries; a project's description and result no longer run together; periods of projects/activities use the same en dash.
* **Wording check:** no on-screen wording was changed. The privacy notice still correctly names the external provider (it still receives the candidate's facts and the vacancy text to rank them). If the founder wants the product pages to say that Azerbaijani documents are composed from the candidate's own words with AI used only for relevance, that is a copy decision.

## 3. Weak points a reader should judge
The composed letter is plain and a little mechanical (quoted requirement + the candidate's own evidence); it is correct and traceable rather than eloquent. The candidate's own wording is used as written, so a Turkish-looking sentence typed by the candidate stays (it is theirs, and they review it before approval). Experience-before-education ordering of the CV is unchanged (Harvard template: education first).

## 4. Tests
`src/resumes` 196 unit tests (language checks and foreign names, first-person conversion, requirement extraction, ids-only validation, outage fallback, missing key, retry limits and feedback, relevance, failure and refund); e2e on the isolated database: documents (24), tailored CV (10), career evidence (12) with the fake provider returning invented employers, skills, certificates and prose that must have no effect.

## 6. Audit of the composition approach (9 October, after the first review round)
| Question | Answer and evidence |
|---|---|
| Can a vacancy requirement become a claim about the candidate? | Not by construction: requirements appear only inside `elandakı «…» tələbi`, attributed to the posting; the candidate's claim is only their own evidence sentence. A model pairing is accepted only when requirement and evidence share a word (deterministic fallback needs two); a certificate is introduced as `Keçdiyim təlim:` (a course), never as experience. Tests: unrelated pairing dropped, certificate wording, posting lines with numbers/links/addresses excluded, injection-style ids ignored |
| Facts, dates, numbers and attribution kept? | Bullets, project/activity/award/certificate/language entries, company, position and periods are the candidate's own text, unchanged (test compares every field). Only a final simple-past "-dı/-di/-du/-dü" verb of the candidate's own action takes "-m" in the letter; results and passives ("oldu", "azaldı", "bağlandı") stay as written, so a number never changes subject |
| Anything relevant discarded silently? | A resume that must drop bullets says so (`trimmed_highlights`); confirmed projects, activities, awards, certificates and languages a CV/resume left out are now named (`left_out_entry`; found and fixed in the journey: notes of kind OTHER are not reported). Stories are letter material and never appear in a CV. A letter uses at most two evidence items by design (the others are not mentioned) |
| Candidate wording mistakes | Kept exactly, pointed out for review without any rewrite (`candidate_wording`): Turkish forms, English function words, present tense in a role that has ended. **Not detected:** missing diacritics or misspellings such as "edirem", unknown words (no Azerbaijani dictionary is available offline) |
| Does the letter connect specific evidence to the role? | Each match is written evidence-first and then linked to the posting's requirement naming the position (`… Bu, {Vəzifə} üçün elandakı «…» tələbi ilə bağlıdır.`). It is a link by shared words, not a judgement that the evidence is sufficient |
| Sparse profiles and provider failure | Tested: no evidence → opening + closing only, nothing invented; no skills/projects → CV from saved facts; provider 503/429/silent → keyword ranking for CV and letter (`ranking-fallback`), document still produced and counted once; no key → fails and refunds |
**Real-provider journey on the DEPLOYED image (`72fba90e34a0`, isolated stack, synthetic candidate, real public vacancy): 41 of 41 checks passed, 0 failed** (quote, replay, drafts without a file, PDFs, edit, approve, file = approved snapshot, 2 of 5 units, Plus 30, Premium uncapped). An earlier run on the previous image failed one check because the driver mistook a paragraph id for a number; it is fixed and was rerun. CI: `main` at `72fba90e` passed on that exact revision.
**Remaining limitations (honest list):** (1) no native reader has approved the sentence frames or the samples; (2) letters are plain and mechanical, and long or unusual vacancy titles and requirement lines are quoted verbatim (they are the employer's words, with the employer's possible Turkish forms); (3) the pairing is lexical: shared words do not prove the evidence answers the requirement, so the candidate must read the letter before approving (approval is required before any file exists); (4) a vacancy with few bullet-style requirements yields prose sentences, so matches are weaker; (5) the quality of the model's ordering is only spot-checked on three candidates; (6) English, Russian and short answers to application questions still use the model-written path with the gate; (7) no check of the Azerbaijani text beyond Turkish/English forms, tense in ended roles and the frames.
