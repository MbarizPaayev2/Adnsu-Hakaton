# Frontend/backend integration of the document experience — review, fixes and real-browser evidence (4 October 2026)

Integrated: Gemini `codex/document-experience` frozen at `bc72d87b10d98d4e472cae0d0bccd69801acd1f4` (it contains backend contract `0465b19`) into `codex/vacancy-email-applications` by merge commit `58666ce`, history preserved. Backend sources were untouched by the integration; everything below was found by reviewing the frontend against the real API and then by running it.

## What the evidence is (and is not)
* **Real:** the Next.js app (served from a throw-away copy of `apps/web`), the NestJS API modules, a disposable Postgres database, Redis/BullMQ under a unique prefix, the document worker, Typst PDFs, storage, the e-mail application pipeline, the guarded import route, and a headless Chrome for Testing driving every screen.
* **Deterministic stand-ins, named as such:** the generation provider is a loopback **fake that is not a language model** (it restates the facts it is given); matching scores come from a fixture scorer; e-mail goes to a loopback **capture sink** (nothing was sent anywhere; non-loopback fetch is refused inside the stack); the vacancies are synthetic postings sent through the real guarded ingestion route.
* **Not evidence of real model quality, live delivery, payments or production.** Gemini's own 338 web tests mock API responses and its earlier screenshots used a fixture server; neither is counted as persistence or end-to-end evidence here.
* Ports 3461 (web), 4420 (API behind a fault-injecting proxy; real API 4421), 4430 (control), 4611 (sink); database `aise_integration_<timestamp>`, dropped at teardown. The founder's 3450/4010/4598 and `aise_local_preview_20261003` were not touched (see the incident note below).

## Review findings, fixed on the integrated branch (each with a regression test)
| # | Defect found in the frozen frontend | Fix |
|---|---|---|
| 1 | Letter composer: a failed server generation fell through to a **locally fabricated draft** (the `catch` did not return) | A real match outside preview mode gets a draft from the server or nothing; failure shows the error on the questions step. Tests: no local draft, no approve button. |
| 2 | `requestId` lived for the whole modal/composer session: after a FAILED document or a changed language/answers the retry **replayed the old outcome forever** (server replays by key) | `lib/documents/request-id.ts`: a key is tied to the exact request and kept only while an identical request has **no answer**; any received answer (or a new session) starts a new key. |
| 3 | An unreadable body behind a **success status** (connection cut mid-answer) was handled as a normal error and rotated the key, so the retry would be **charged twice** | A success status without a readable body is an unknown outcome: same key, honest message. Verified in the browser with a truncated response. |
| 4 | Quote refusal read as a string; the server sends `{code, …}`. Concurrency/hourly protections were worded as "balance exhausted, upgrade" | `lib/documents/refusal.ts`: separate wording for month-exhausted (with Baku reset time) and the short protections (stated as not monthly, no upgrade prompt). |
| 5 | Stale quote kept on screen and usable while the next one loaded; `1 generasiya` shown when no quote existed | Quote cleared on every input change; cost shows `—` without a quote. |
| 6 | Vacancy label used `job.companyName` (the API sends `job.company`): every match showed "Şirkət" | Fixed mapping. The modal also re-fetched matches on every selection (select unmounted, focus lost) | Loaded once. |
| 7 | "Include sections" checklist in the modal was never sent to the server | Removed; text explains selection happens in review. |
| 8 | Letter answers: if the STORY could not be saved the letter was generated **without** the candidate's answers, silently; the 409-path PATCH was unchecked | Generation stops with the server's message. |
| 9 | Composer's "confirmed projects/certificates" came from `parsedContent.evidence`, a field the API does not have, so **nothing was ever offered** | Loaded from `/profile/career-entries?status=CONFIRMED`; only confirmed entries. |
| 10 | Career periods: the editor displays `2022-05 - 2023-01` but its parser split on every hyphen, so editing a month range **silently turned it into a year**; an unreadable text was silently ignored; mixed year/month precision invented a month | `parsePeriodStrict`: exact reading or a named error; the whole save is validated **before the first request** so nothing is half-saved. |
| 11 | Every career-editor label was unassociated with its input (no accessible names, tap-on-label did nothing) | `htmlFor`/`id` on all 16 fields; accessibility test. |
| 12 | Document list treated letters as CVs (CV review for a letter, `cv-vN.pdf`, retry of a failed letter/resume created a CV); CV selector in the e-mail page listed letters | Kind-aware list (label, language, review route, file names, kind-correct retry); letters open in the composer; the CV selector excludes letters. |
| 13 | Allowance card read once on mount: stale after generation | Re-reads whenever documents change; keeps last numbers while refreshing. |
| 14 | Reset time printed `2026 M11 1` in browsers without Azerbaijani locale data (including Chrome for Testing) | Baku date formatter with built-in Azerbaijani month names. |
| 15 | Modal did not move focus in (first Tab went to the page behind); no restore beyond the original handler | `use-dialog-focus.ts`: focus in, Tab/Shift+Tab contained, Escape, focus returns to the opener. |
| 16 | Narrow screens: document row title ran under the PDF button at 320 px; review buttons 38 px tall | Row stacks; `min-h-11` on review actions. CV/resume review gained a free **PDF preview** button (`/documents/:id/preview`). |

Not changed, noted: web lint is not a CI gate and reports many pre-existing `any`/hook warnings in files from before this work and in the new frontend; CI gates are typecheck and unit tests.

## Real browser journeys (`apps/api/test/documents-integration-journeys.ts`, 19 checks, last full run all passed)
1. **Career evidence:** wizard upload of a synthetic DOCX; project period edited to a month range, entries confirmed, saved, refreshed and re-logged-in (values persist); a pre-existing STORY and OTHER entry stay byte-identical through every save; "Rus dili" has no level and stays `null` in the UI and the API; an unreadable or mixed-precision period is refused before any request; a PATCH whose answer is lost is retried without duplicating or deleting; explicit delete removes only that entry.
2. **Documents:** quote and allowance shown before generation; resume stays PENDING while the provider is held (no content, no file, one RESERVED unit); draft → factual review → free edit → manual approval; the approved PDF contains the reviewed wording; preview bytes = approved file = APPROVED snapshot hash; letter in English from confirmed answers saved as a STORY (sent to the provider as letter facts), pending without a fabricated draft, server draft, edit, approve; allowance 2 used after resume + letter, nothing for edits or downloads.
3. **Failures:** a generation answer cut mid-body is reported as unknown and the retry is replayed (one document, one charge); a failed review save (injected outage) → the approval request is never sent, nothing stored, retry saves then approves — for both the CV/resume review and the letter composer; another candidate gets 404 on every document route and sees nothing in the browser.
4. **E-mail application:** from the real vacancy page; recipient evidence (quoted wording, source link, last-seen date); a letter written for another vacancy is refused; the approved CV and letter for this vacancy are attached with their hashes; a CV re-approved after the preview makes approval fail (still awaiting approval, nothing sent); the capture sink received one message with the approved CV and letter **byte for byte**, and the approved payload hash was recomputed from the stored bytes; page wording: "E-poçt xidməti qəbul etdi" → after a signed webhook "Qəbuledicinin poçt serveri qəbul etdi", both with the statement that this is not an employer reaction, `employerConfirmed: false`.
5. **Responsive:** list, create modal (focus contained both directions, Escape, focus returns, touch targets ≥ 44 px), review + PDF preview (opens as a blob tab), career editor, e-mail page, letter composer at 320/390/768/1440 px: no horizontal overflow, no overlapping controls.

## Running it
From `apps/api`: `npx ts-node -r tsconfig-paths/register --transpile-only test/support/integration-stack.ts` (starts everything, prints READY), then `… test/documents-integration-journeys.ts all` (creates two synthetic candidates and runs every journey; the candidates and their documents remain visible at the printed web address until the stack is stopped with SIGTERM, which also drops the disposable database, the queue keys and the temporary web copy). Screenshots are written to `/tmp/aise-integration-shots` and are not committed.

## Incident note
At about 01:2x on 4 October the founder's preview processes (launcher 7043 serving 4010/4598, web 7050 on 3450) were found no longer running. They were not stopped by this work (no command matched them, nothing was killed outside this stack, and their database was only read for its migration count). Their launcher stops itself when free disk falls below 3 GiB and this machine's data volume is at 97 % (≈7 GiB free); the integration stack, browser runs and builds used disk during that window, so a disk-triggered self-stop is the most likely cause but is **not proven**. The preview database `aise_local_preview_20261003` has 38 migrations (without the five new ones), so restarting the preview from this branch needs those migrations applied to it, which is the founder's decision and was not done.
